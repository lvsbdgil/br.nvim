# Linux: установка и настройка br.nvim

Плагин выводит видео поверх текста Neovim внутри локального окна Kitty.
Команда `:br` запускает и останавливает воспроизведение. Звук не воспроизводится.
Нужны Python 3.9+, FFmpeg, Kitty, `ps` и **Neovim 0.12+**.

## 1. Скачай приватный репозиторий

Авторизуй Git для GitHub (SSH-ключ или GitHub CLI). Например, если `gh` уже установлен:

```sh
gh auth login
mkdir -p "$HOME/Projects"
gh repo clone lvsbdgil/br.nvim "$HOME/Projects/br.nvim"
cd "$HOME/Projects/br.nvim"
```

С настроенным SSH вместо `gh repo clone`:

```sh
git clone git@github.com:lvsbdgil/br.nvim.git "$HOME/Projects/br.nvim"
cd "$HOME/Projects/br.nvim"
```

Альтернатива: скачай ZIP через авторизованный браузер на GitHub, распакуй в постоянную
папку и открой там терминал. Для такой копии автоматическое обновление через Git недоступно.
Не перемещай каталог после установки: плагин подключается к нему символической ссылкой.

## 2. Установи зависимости

Сначала можно посмотреть команды без установки:

```sh
bash scripts/linux-deps.sh --dry-run
```

Затем установить:

```sh
bash scripts/linux-deps.sh
```

Скрипт выбирает пакетный менеджер: apt (Debian/Ubuntu/Mint), dnf (Fedora),
pacman (Arch/Manjaro) или zypper (openSUSE). Для системных пакетов используется sudo.
На Arch запускается `pacman -Syu`, включая обновление системы, чтобы избежать частичного обновления.
На Fedora используется `ffmpeg-free`; доступность декодера конкретного видео зависит от сборки.
Пакеты должны присутствовать в подключённых репозиториях. Скрипт не добавляет сторонние репозитории.

На другой системе установи вручную: git, curl, ca-certificates, Python 3.9+, FFmpeg,
Kitty, Neovim 0.12+, ps (procps/procps-ng), tar и gzip.

## 3. Проверь версию Neovim

```sh
nvim --version
nvim --headless -u NONE '+lua print(vim.api.nvim_ui_send ~= nil)' +qa
```

Последняя команда должна вывести `true`. Некоторые дистрибутивы поставляют более старую версию.
В таком случае установи официальную стабильную сборку для x86_64 или ARM64:

```sh
python3 scripts/install-neovim.py --dry-run
python3 scripts/install-neovim.py
```

Скрипт получает текущий stable-релиз из GitHub API, проверяет SHA256 из метаданных релиза,
проверяет наличие нужного API и устанавливает Neovim в `~/.local/opt/br-neovim-...`.
Ссылка на бинарник создаётся в `~/.local/bin/nvim`. Системный Neovim остаётся доступен.
Чужой файл `~/.local/bin/nvim` скрипт не перезаписывает.

Для текущего сеанса Bash/Zsh:

```sh
export PATH="$HOME/.local/bin:$PATH"
hash -r
nvim --version
```

Чтобы сохранить PATH, добавь строку `export PATH="$HOME/.local/bin:$PATH"` в `~/.bashrc`
для Bash или в `~/.zshrc` для Zsh. Для Fish используй `fish_add_path ~/.local/bin`.
Заново открой Kitty и проверь `command -v nvim`.
Если официальная сборка не запускается из-за glibc, используй совместимую сборку своего
дистрибутива или собери Neovim по официальной инструкции.

Источники: [установка Neovim](https://neovim.io/doc/install/),
[официальные релизы](https://github.com/neovim/neovim/releases).

## 4. Открой Kitty

Запусти Kitty из меню приложений или командой `kitty`. Дальнейшие действия выполняй в нём.

```sh
printenv KITTY_WINDOW_ID
```

Должен появиться номер окна. Нужен локальный графический сеанс Wayland или X11;
Linux-консоль без графики, SSH, tmux, Windows Terminal и Ghostty не поддерживаются этой версией.
Настраивать remote control Kitty для плагина не нужно.

Если Kitty из дистрибутива слишком старый, используй
[официальную инструкцию установки](https://sw.kovidgoyal.net/kitty/binary/).
Официальный установщик допускает `launch=n` для установки без автоматического запуска.

## 5. Установи плагин и укажи видео одной командой

Положи видео в постоянное место. Например, `~/Videos/test.mp4`.
Путь с пробелами обязательно заключай в кавычки:

```sh
cd "$HOME/Projects/br.nvim"
python3 scripts/br.py install --video "$HOME/Videos/test.mp4"
```

Скрипт создаёт:

- ссылку `~/.local/share/nvim/site/pack/local/start/br.nvim` на скачанный репозиторий;
- настройки `~/.config/nvim/after/plugin/br-settings.lua` с выбранным видео и размерами.

Учтены `XDG_DATA_HOME`, `XDG_CONFIG_HOME` и `NVIM_APPNAME`, если ты используешь другой профиль.
Запускай установку без sudo: файлы относятся к твоему пользователю.
`init.lua` не меняется. Если уже есть другая установка плагина, скрипт остановится;
перенеси прежний каталог за пределы `pack/.../start` и повтори команду.
Для замены существующего файла настроек с резервной копией добавь `--force`.

Без `--video` используется `~/Movies/test.mp4`, одинаково на Linux и macOS.
Видео не копируется и не пережимается; в конфигурации сохраняется абсолютный путь.

## 6. Диагностика и первый запуск

```sh
python3 scripts/br.py doctor --video "$HOME/Videos/test.mp4"
nvim
```

Doctor проверяет программы, нужный API Neovim, установку, видео через ffprobe и окружение Kitty.
При ошибках возвращает ненулевой код. Из обычного терминала можно выполнить статические проверки:

```sh
python3 scripts/br.py doctor --no-terminal --video "$HOME/Videos/test.mp4"
```

Doctor не читает произвольный Lua для определения видео: передавай тот же `--video`, что при установке.
Он выводит путь и содержимое файла настроек для сверки.

В Neovim: `Esc` → `:br` → Enter. Повторный `:br` выключает видео.
Проверь прокрутку текста, изменение размера окна и повторный запуск.
`:BR` — полная команда; для скриптов используй её или `require('br').toggle()`.

## 7. Размеры и отступы

```sh
python3 scripts/br.py configure \
  --video "$HOME/Videos/test.mp4" \
  --columns 96 --rows 64 \
  --margin-top 1 --margin-right 2
```

Ширина/высота задают максимальную область в ячейках терминала; пропорции видео сохраняются.
Отступ сверху задаётся в строках, справа — в столбцах. Для уменьшения вдвое: `48` и `32`.
Команда записывает все параметры, поэтому указывай свой путь к видео при каждой настройке.
Предыдущая изменённая конфигурация сохраняется рядом как `.backup-ДАТА`.
Перезапусти Neovim, чтобы прочитать файл заново.

Для временной настройки без перезапуска:

```vim
:lua require('br').setup({ columns = 48, rows = 32 })
```

## 8. Обновление и удаление

Обновить исходники из приватного GitHub-репозитория:

```sh
python3 scripts/br.py update
```

Нужен доступ Git к репозиторию. Скрипт требует чистую рабочую копию и использует
`git pull --ff-only`. После обновления перезапусти Neovim.

Удалить подключение плагина:

```sh
python3 scripts/br.py uninstall
```

Сначала закрой Neovim. Удаляется только ссылка на эту копию репозитория.
Созданный скриптом файл настроек переносится в резервную копию. Сам репозиторий,
видео и системные пакеты остаются. Чужие установки скрипт не удаляет.

## 9. Типовые ошибки

- **Нет `:BR`**: проверь `:echo exists(':BR')` (ожидается `2`) и совпадение XDG/NVIM_APPNAME
  при установке и запуске. Не запускай с `--clean`, `-u NONE` или `--noplugin`.
- **Старый Neovim**: проверь `command -v nvim`, PATH и шаг 3.
- **Декодер остановлен**: открой `:messages`; проверь `ffprobe` и пакет `ps`.
- **Нет видео**: проверь абсолютный путь, `doctor`, локальный Kitty и отсутствие tmux/SSH.
- **FFmpeg не декодирует файл**: проверь поддержку его кодека в сборке своего дистрибутива.
- **Нет доступа к GitHub**: проверь `gh auth status` или SSH-ключ и доступ к приватной репе.
- **Видео пропадает при `redraw!`**: изображение восстанавливается на следующем кадре.
- **Видео без звука**: эта версия воспроизводит только изображение.

## Автоматические проверки исходников

```sh
python3 -m unittest discover -s tests -v
bash -n scripts/linux-deps.sh
```

Тесты используют временные каталоги и не меняют рабочую конфигурацию Neovim.
Они проверяют установку, повторный запуск, резервные копии, защиту чужих файлов,
пути с пробелами/кавычками и поиск tty Linux/macOS.
Визуальное воспроизведение проверяется отдельно в реальном окне Kitty.
